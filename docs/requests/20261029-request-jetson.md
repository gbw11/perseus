## 현재 할 일과 읽는 순서

1. [주행 설계](../platform/drive-pipeline-architecture.md) 2·5~8·18~20절에서 장비·broker·바이너리·좌표/시각·책임을 읽습니다.
2. 같은 문서 10·12절의 Pi 소비·상태 인계와 [복구 시나리오](../platform/recovery-scenarios.md)의 A5·B4·H1·지도 복원 사례를 읽습니다.

## 플랫폼 제공물과 선행 결정

Pi는 기존 netfront·직접 MQTT·공통 실행/진단 기반을 제공합니다. 실제 지도 decoder·planner·입력 연결의 미구현 범위를 그때그때 구분합니다. `.proto` tag·소형 상태 형식·frame/시각 대응·array/packet/pool 상한은 생산자/소비자 공동 결정이고 예시 80×80/3byte/10Hz를 운영 상수로 복사하지 않습니다. Jetson 입력 부재가 정상 MANUAL의 새 필수조건이 되어서는 안 됩니다.
