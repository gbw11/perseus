# ESP32·차량 피드백·적용 확인 구현 요청

대상: ESP32·차량 제어 담당자. **상태: 요청 작성 / 실제 MCU 제품 소스·차량 적용·수락 전.** 이 저장소에서 ESP32 펌웨어 위치는 확인되지 않았습니다. 착수 시 실제 저장소·파일·설치/보정 버전을 연결합니다. Pi의 시리얼 encoder 성공은 MCU 구현·적용 성공이 아닙니다.

## 현재 할 일과 읽는 순서

1. [주행 설계](../platform/drive-pipeline-architecture.md) 2·7·11~14·19~20절을 읽습니다.
2. `platform/services/gateway/xenova_gateway/frame.py`, `sink.py`, `tests/test_frame.py`와 [기존 차량 명세](../design/vehicle-control-spec.md)를 대조합니다. 현행 encoder 주석에는 세션 hello/ack가 아직 없다고 명시되어 있으므로 이미 지원한다고 가정하지 않습니다.
3. [Gateway 직접 구현·공동 연동](20261029-request-gateway.md)의 제출/적용/실제 정지 경계와 아래 조건을 공동 확정합니다.

## 제공물과 남은 결정

Gateway는 단일 출력 소유·원 generation·시리얼 제출 근거를 유지합니다. MCU의 적용·실제 이동·정지는 장치 원천으로 확인해야 합니다. 새로운 세션·ACK 형식·feedback 크기/주기·시계 대응·허용 중단은 기존 프로토콜과의 호환·파서 상한·고정 벡터를 함께 확정한 뒤 구현합니다. 이 요청으로 프로토콜 전체 교체나 실제 모터 구동을 승인한 것은 아닙니다.

## 진행 기록
