# 카메라 화면 표시 경계 v1

2026-10-26 · S15P31E110-252. 기존 프론트가 참조하던 경로의 표시 계약이다. 송신기·프록시가 실제 배치됐다는 뜻은 아니다.

- AI·인식 주체는 Jetson이다. Debian VM3는 인터랙션·영상 표시를 담당할 수 있지만 이 사실만으로 AI 추론을 수행한다고 표시하지 않는다.
- 기존 앱 미리보기의 `CameraView`/`NavCamera`는 `VITE_CAMERA_URL` 또는 same-origin `/camera/stream.mjpg`의 MJPEG를 표시한다. 전송 소스와 프록시 구축·접근 제어는 별도 연결 사항이다.
- 카메라 스트림은 로컬 HDMI 화면 픽셀을 전송하는 표시 송신기의 `/streams/{output_id}.mjpeg`(상태는 `GET /api/v1/streams`)와 다른 소스다. 카메라 수신 성공으로 HDMI 원격 시연 성공을 주장하지 않는다.
- 카메라 단절은 영상 수신 오류로 표시한다. 차량 모드·활성 VM 변경이나 VM 재시작 명령을 영상 상태에서 만들어내지 않는다.
- mock 합성 영상은 실제 Jetson 영상·물리 카메라·AI 결과 수신 증거가 아니다. 현재 canonical `/display/*` 화면은 상태 패널이며 그래픽·카메라 어댑터가 없는 경우 연결 대기를 표시한다.
- 향후 실제 연결 시 송신 주체, 접근 가능한 URL/인증 방식, 해상도·FPS·유효기간을 담당자와 확정하고 문서에 측정 근거를 추가한다. 서비스 토큰은 프론트 환경변수나 URL에 넣지 않는다.

## 연결 구성 (S15P31E110-263, 2026-11-03)

화면 쪽 주소는 바꾸지 않는다. 콘솔·`/screens` 미리보기는 계속 same-origin `/camera/stream.mjpg` 를 쓰고, **무엇이 그 뒤에 있는지는 웹 프록시의 upstream 하나로 고른다.**

| 구성 | `/camera/` upstream | 영상 |
| --- | --- | --- |
| 시뮬레이터 시연 (젯슨·실카메라 없음) | `http://<시뮬레이터 PC Tailscale IP>:8090` (`python -m xenova_simulator ... --camera 0.0.0.0:8090`) | 시뮬레이터 전방 카메라 **원본**, 320×240·15 fps. 감지 박스 없음 |
| 실제 카메라 | 실제 송신기(젯슨/세 번째 VM) 주소 — 송신 주체 확정 후 기록 | 미정 (위 "향후 실제 연결") |
| 미설정 | 닿지 않는 주소(기본값) | 502 → 화면은 영상 수신 오류 표시·3초 재시도 |

- 시뮬레이터 화면과 `perception.result` 는 같은 MJPEG 를 본다. 인지(`--source stream --url`)가 읽는 주소와 패널이 프록시로 받는 주소의 출처가 같아야 장면과 결과가 맞는다.
- 시뮬레이터 영상은 합성 영상이다. 이를 실제 Jetson 영상·물리 카메라 수신 증거로 쓰지 않는다 (위 경계 그대로).
- 패널이 보여 주는 것은 원본이다. 인지 결과(박스)를 그린 영상은 아직 송신 주체가 없다.
- 프록시는 MJPEG 를 버퍼링하지 않아야 한다 (`proxy_buffering off`, 긴 `proxy_read_timeout`).
- 실제 구성 근거: [검증 기록](../verification/sim-camera-263-20261103.md).
