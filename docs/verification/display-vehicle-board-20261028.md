# 차량 HDMI 화면 변경·실보드 검증 (2026-10-28)

사용자가 확정한 화면 구성에 맞춰 기존 VM 전체/상세 HDMI 렌더러를 차량 화면으로 교체했다. 외부 웹 관리자 콘솔은 변경하지 않았다.

| 출력 | 새 구성 | 실제 데이터 연결 상태 |
| --- | --- | --- |
| HDMI 1 | 계기판: 속도·배터리·확정 주행 모드·경고·정적인 차량 대기 연출 | 모드는 기존 표시 전용 제어 상태 계약 사용. 실제 속도·배터리 송신 연결 없음 → `—`, 수신 대기 |
| HDMI 2 | 네비·음악·주행 모드·켜진 VM·선택 게스트 콘텐츠·오류/작업 알림 | Xen 실행 상태만 이번 시험에서 실제 수신. 네비·음악·게스트 영상 어댑터 없음 → 수신 대기 |

## 정책·동작

- presentation.outputs의 새 `screen` 필드는 monitor-1=`instrument`, monitor-2=`infotainment`로 고정한다. 기존 `view` 필드는 이전 선택 API 호환용이다. 새 UI는 이 필드로 전체/상세 모양을 결정하지 않는다.
- 게스트 콘텐츠 선택은 기존 pinned/follow_active UUID 선택을 유지한다. 현재 기본 선택은 VM1이며 선택 API로 VM3 등을 지정할 수 있다. 네비·음악 영역과 차량 화면의 역할은 VM 선택과 별개다.
- 모드와 활성 구동 VM은 신선한 제어 보고에서만 표시한다. VM2 백업 역할을 수동주행으로 해석하거나, VM 장애를 보고 표시기가 제어권을 바꾸지 않는다.
- 화면 연결 또는 Xen 관측이 오래되면 켜짐·주행 모드의 현재 상태 주장을 제거한다. 게스트 화면 핸들을 URL로 사용하지 않는다.
- HDMI 2에 별도 상태 요약/OS 진단 패널을 두지 않았다. 켜진 VM은 작은 표시로, 주요 영역은 콘텐츠용으로 사용한다.
- 오류·작업 알림은 현재 VM 정책 결정만 사용한다. 아직 연결되지 않은 실제 복구 완료 사건을 생성하거나 완료됐다고 표시하지 않는다.

## 자동 검사

- 프론트 빌드 성공, 해당 화면·모델 검사 10개 통과, 수정 프론트 파일 ESLint 통과.
- 표시 수집기 전체 회귀 138개 통과. VM 장애에도 차량 화면 역할이 바뀌지 않는 assertion 추가 후 정책 검사 16개 재확인 통과.
- Windows 기본 Python에는 FastAPI/Pydantic이 없어 최초 수집이 실패했다. 기존 의존성이 설치된 WSL 가상환경에서 위 검사를 실행했다. 별도 시스템 패키지는 설치하지 않았다.

## 실제 보드 확인

- 보드 한 모니터에 새 두 화면을 각각 30초씩 표시했다. 사용자가 **“새 두 화면이 정상 크기로 보였음”**이라고 확인했다.
- 두 화면의 실제 X11 캡처 JPEG를 직접 열어 확인했다. 각 뷰포트와 문서 크기는 모두 1824×984로 넘침이 없었다.
- 동일한 새 웹 빌드로 실제 FFmpeg → 인증된 기존 MJPEG 서버 → 고정 호스트 키 SSH → PC HTTP 수신을 수행했다. 두 화면 각각 첫 연결 20프레임 + 재연결 20프레임, 총 80프레임을 받았다.
- 무인증/오인증은 401, 정상 로그인 204, 세션 쿠키 조회 200. 소스를 해제하면 이전 프레임을 제공하지 않았다.
- 대기 화면이 정적이므로 JPEG 해시가 같은 것은 정상이다. multipart 프레임 수신과 실제 인코더 프레임 순번 증가를 따로 확인했다. 수신 시각만으로 p95 지연이나 정식 5 FPS 성능 통과를 주장하지 않는다.
- 시험 후 framebuffer는 원래 바이트와 일치했다. VT1 복귀, 임시 그래픽 프로세스·마운트 없음, 8082 포트 닫힘, 기존 Manager 8081 유지, VM 3대 실행 유지까지 조회했다.
- fbdev는 EDID를 노출하지 않아 기존과 같은 명시적 단일 framebuffer 진단 매핑을 사용했다. `physical_verified=false`이며 두 HDMI 동시 출력/운영 Kiosk 배치 검증은 아니다.

## 보드 배치

새 웹 파일과 검증한 수집기·정책 소스를 `/opt/xenova-display-probe/20261028-vehicle-457565587e67`에 보관했다. 기존 설치본을 수정하지 않고 시험 디렉터리에 라이브러리를 복사했으며, 실제 소스 해시와 새 경로에서 정책을 import하는 것까지 확인했다. 웹과 수집기를 함께 사용하는 시험 배치이며 부팅 자동 시작/영구 서비스 교체는 수행하지 않았다.

## 남은 연동

속도·배터리의 실제 송신 계약과 측정값, 네비·음악 앱 데이터/화면, 재생 가능한 게스트 영상 어댑터, 실제 복구 사건의 표시 연결은 아직 필요하다. 주행 제어 명령을 속도 측정값으로 대신 쓰거나 허위 콘텐츠를 채우지 않았다. 외부 서버·두 모니터 동시 출력·부팅 자동 실행·정식 성능 수락도 별도다.
