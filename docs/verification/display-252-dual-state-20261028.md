# 252 두 HDMI 상태 전환·정상 복귀 검증 — 2026-10-28

## 결과

252 브랜치의 계기판·인포테인먼트를 실제 Pi4의 서로 다른 HDMI에 1280×720로 띄우고, 격리된 시험 수집기의 상태를 바꿔 렌더링을 검증했다. **13단계 × 2출력 = 26개 확인을 통과**했다. 앱/주행 정상·정지·일시정지·작업 진행·미수신·지연은 합성 입력이며, 실제 VM 장애나 펌웨어/주행 복구를 일으키지 않았다. 캡처에 TEST ONLY 표식을 붙였다.

| 입력 | 두 화면 확인 |
|---|---|
| 합성 정상 | AUTO, VM1 활성 표시; 속도·배터리는 여전히 미수신 |
| 일시정지 | VM1 일시 정지 알림, 인포테인먼트의 켜짐 표시 제거 |
| 정지 | VM1 정지 알림, 인포테인먼트의 켜짐 표시 제거 |
| 작업 진행 | VM 작업 진행 중, 복구 완료·VM2 승계로 추정하지 않음 |
| 최초 미수신 | 상태 수신 대기, VM1 실행 미확인 |
| Xen 상태 지연 | VM 상태 수신 지연/연결 끊김, VM1 켜짐 표시 제거 |
| HTTP 503 | 표시 연결 끊김·현재 값 미확인, 이전 AUTO 표시 제거 |
| 각 입력 뒤 정상 | 이전 상태 알림 제거, 현재 정상 결정 반영 |

모든 단계에서 두 창의 전체화면 좌표와 1280×720 viewport를 유지했다. scrollHeight=720, footer 하단≤720을 확인했다. 실제 X11 영역 캡처에서 정지·작업 진행·연결 끊김·정상 복귀를 직접 열어 확인했다. 이번 상태별 시각 검사는 캡처·DOM으로 수행했으며 사용자 육안 확인으로 기록하지 않았다.

## 수정과 검증

- 계기판 알림에서 빠졌던 정지·일시정지·종료 중·최초 미수신·OS 불일치 결정을 두 화면 알림에 표시한다. 서버 결정 라벨을 사용하며 임의 복구 완료를 만들지 않는다. 정지는 정지용 배지를 사용한다.
- 각 출력에서 5개 상태 → 정상 전환을 확인하는 10개 회귀 사례를 추가했다. 표시 테스트 30개, vm-screens production 빌드(타입 검사 포함), 변경 TSX ESLint·Prettier 검사를 통과했다.
- 기존 252 미커밋 변경인 720p 잘림 방지·설정 OS/관측 OS 구분·실행 연결 미검증 표시도 포함했다. 이전 상세 시험은 [이전 보드 검증](display-252-board-render-20261028.md)에 있다.
- 제품 254 DisplayPolicy와 조회 전용 Xen driver를 사용했다. 실제 VM 3대 식별 매핑을 유지하되 반환 스냅샷만 시험용으로 바꿨다. 정지 알림만으로 주행 모드나 활성 VM을 임의 변경하지 않았다.
- 256의 KMS modesetting/EDID 시험 실행부를 재사용했다. 정식 자동 시작 서비스 경로를 검증한 것은 아니다. 인증된 loopback 시험 feed를 사용했고 제품에 fixture endpoint·인증 우회 기능을 추가하지 않았다.

## 종료와 한계

시험 feed와 그래픽 프로세스를 종료하고 VT1으로 복귀했다. 별도 SSH 조회에서도 그래픽 프로세스·private mount 없음, systemd failed 0, 기존 listener 22·8081, Debian/VM1/VM2 domid 1/2/3 유지를 확인했다. 보드 재부팅·게스트 명령·시스템 서비스/펌웨어 변경은 없었다.

이번 framebuffer 원본 복원 직후 바이트 비교는 **32바이트 차이(framebuffer_restored=false)**였다. 크기는 전후 1920×1080으로 동일했고 콘솔 VT1 복귀는 확인했다. 커서/콘솔 동시 갱신 여부는 확정하지 않았으며, 이전 시험의 0바이트 차이 결과로 이번 값을 대체하지 않는다. 따라서 이번 실행의 픽셀 단위 완전 동일 복원은 통과로 계산하지 않는다. 이는 26개 렌더링 항목의 통과와 별도 정리 관측이다.

252의 로컬 렌더링·합성 상태 전환 검증은 수행했다. 실제 주행/복구 이벤트, domU 앱 영상·내비·음악 연동은 253·255의 통합 의존성이다. 256 서비스 기동·장애 복귀나 257 원격 성능 완료를 뜻하지 않는다. 외부 웹 라우팅은 범위 밖이다.

커밋·푸시·MR 생성·지라 상태 변경은 하지 않았다. 현재 252 작업 브랜치에 코드와 증거를 보관했다.
