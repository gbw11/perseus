# 252 — 차량 HDMI 렌더러 실보드 검증과 720p 보완

2026-10-28. 최신 `platform` ef79127에서 `feat/platform/S15P31E110-252-board-render-check`를 만들었다. 257의 절전·인코딩 보완은 이미 이 platform에 병합돼 있다. 이번 변경은 렌더러와 표시 검증에 한정하며 platform 브랜치 자체는 변경하지 않았다.

## 현재 화면과 실제 시험 범위

- 모니터 한 대에서 `/display/monitor-1` 계기판과 `/display/monitor-2` 인포테인먼트·게스트 데이터를 순차 표시했다. 과거 전체 VM/상세 화면 구성을 다시 사용하는 시험이 아니다.
- Raspberry Pi dom0의 실제 Xen 실행 상태를 read-only driver로 조회하고, 실제 fbdev Xorg와 sandbox가 유지된 Chromium에서 production 빌드를 실행했다. 보드 framebuffer는 1824×984다.
- 오류·작업 진행·AUTO/MANUAL·OS 보고·잘못된 UUID/역할/출력 매핑은 **격리된 시험 수집기의 snapshot에만 합성 입력**했다. 화면에 노란 `TEST ONLY` 표식을 띄웠다. MQTT는 비활성화했으며 실제 게스트 보고·장애·주행 제어를 시험한 것이 아니다.
- 표시 API의 503·고정 sequence·잘못된 응답을 통해 실제 브라우저의 useDisplay/parsePresentation/SnapshotOrder 경로를 검증했다. 운영 API 중단이나 네트워크 설정 변경을 하지 않았다.
- 크기 시험은 실제 X11 브라우저 창의 내부 viewport를 1280×720으로 조절했다. DOM scroll 크기·footer 위치·게스트 콘텐츠 영역의 경계를 확인하고 실제 X11 JPEG도 직접 열어 확인했다. 물리 HDMI 출력 모드를 변경하거나 EDID 매핑을 검증한 것은 아니다.

## 발견한 문제와 수정

1. 낮은 화면 높이용 CSS가 인포테인먼트 영역을 오히려 크게 지정해 720p에서 footer가 740px, 전체 높이가 750px까지 내려갔다. 영역 높이와 음악/게스트 비율·여백을 조정했다.
2. 계기판은 720p에서 연결 끊김 경고 배너가 나타나면 footer가 752px까지 내려갔다. 경고가 있는 경우 계기판 높이를 별도로 줄였다. 최종 시험의 footer는 697px로 화면 안에 들어왔다.
3. 게스트 콘텐츠에 OS 보고 구분이 빠져 있었다. 선택한 VM의 **설정 OS**와 **OS 보고**를 분리해 추가했다. heartbeat나 역할만으로 관측 OS를 만들지 않는다. 보고 없음은 미수신, inventory 지연은 현재 OS 미확인, HTTP 단절은 OS 보고 연결 미확인이다. fresh 보고라도 current_run_verified=false이면 실행 연결 미검증을 명시한다. VM3 선택 시 Debian만 보이며 VM1의 Zephyr 보고를 가져오지 않는다.

## 시험 이력

실패를 보존했으며 세 실행의 수치를 합쳐 모두 통과했다고 표시하지 않는다.

| 실행 | 결과 | 발견/후속 조치 |
| --- | --- | --- |
| 최초 전체 상태·렌더 시험 | 43/44 | 인포테인먼트 720p 잘림 발견 |
| OS 표시·인포테인먼트 보완 후 확장 시험 | 53/54 | 계기판 720p 단절 배너 잘림 발견 |
| 최종 관련 항목 집중 재시험 | **20/20** | 두 화면의 정상·오류·단절·복귀, OS 표시 및 720p 경계 통과 |

최종 수정은 계기판의 720p 단절 배너 높이 CSS에 한정했으며, 관련 두 화면의 레이아웃·연결 단절과 복귀를 집중 재시험했다. 앞선 전체 상태 시험의 다른 항목을 최종 실행에서 모두 반복한 것은 아니다.

## 확인한 표시 동작

| 입력/상황 | 실제 렌더 확인 |
| --- | --- |
| 실제 Xen 조회, 앱/주행 보고 없음 | VM 실행 관측과 앱·모드 미확인을 분리, 속도·배터리는 계속 대기 |
| AUTO→MANUAL 합성 보고 | VM1 활성 UUID 유지, 모드만 변경; VM2를 수동 전용 VM으로 표현하지 않음 |
| 앱 오류·작업 진행·VM 장애 합성 입력 | 해당 경고 표시, 복구 완료나 VM2 승계를 추정하지 않음 |
| Xen stale·최초 미수신 합성 입력 | 현재 정상/켜짐 표식을 유지하지 않음 |
| VM3 선택 및 OS 보고 합성 입력 | VM3/인터랙션·Debian 표시, 다른 VM의 OS 보고 혼입 없음 |
| OS 보고 미수신·fresh/실행 미검증·지연 | 설정값과 관측값·현재 실행 검증 상태를 구별 |
| 등록되지 않은 선택 UUID·중복 역할·잘못된 출력 screen | 응답 거부, 표시 연결 미확인·마지막 선택 안내로 전환 |
| HTTP 200이나 같은 sequence 반복 | 화면을 계속 실시간 정상으로 표시하지 않음 |
| 시험 API 503→정상 응답 | 모드·VM 실행·OS를 미확인으로 표시한 뒤 최신 응답으로 복귀 |
| 1280×720 정상·앱 오류·503·재접속 | 두 화면의 scrollHeight=720, footer≤720, 게스트 텍스트가 패널 내부에 있음 |
| 원래 fullscreen 복귀 | 두 페이지 모두 viewport 1824×984 복귀 |

최종 720p footer 위치는 계기판 정상 687px / 오류 693px / 단절 697px, 인포테인먼트 정상 685px / 오류 691px / 단절 685px다. 초기 실패 이미지와 최종 화면 캡처를 증거 폴더에 함께 남겼다. 새 화면의 사용자 육안 확인을 별도로 받은 것은 아니며, 이번 시각 검사는 실제 framebuffer JPEG를 직접 열어 수행했다.

## 코드 검증과 정리

- 프론트 표시 테스트 20개 통과(기존 15개 + OS 정보 구분 5개). vm-screens 타입 검사·production 빌드, 변경 TSX의 ESLint, 변경 파일 Prettier 및 git diff --check 통과.
- 세 보드 실행 모두 namespace_exit=0, feed·그래픽 자식 프로세스 종료, VT1 복귀, 원래 framebuffer와 0바이트 차이로 복원됐다.
- 마지막 별도 SSH 조회에서도 그래픽 프로세스·private mount가 없고 listener는 기존 SSH 22와 Manager 8081뿐이었다. VM3 domid1, VM1 domid2, VM2 domid3가 유지됐다.
- 실제 VM·펌웨어·부팅 이미지·기존 서비스·자동 시작·네트워크 정책을 변경하지 않았다. 시험 stage 파일은 격리된 `/opt/xenova-display-probe/` 경로에 남는다. 인증 토큰·비밀번호는 증거 자료에 저장하지 않았다.

## 완료 범위와 의존성

이번 **252의 차량 화면 보완·렌더링 검증 범위**를 마쳤다. 실제 앱 영상·내비/음악·속도/배터리는 아직 어댑터/보고가 연결되지 않아 대기 표시다. 실제 OS·앱 보고와 실행 세대 연결은 253, 실제 제어·복구 상태와의 통합은 255에서 확인해야 한다. 실제 두 HDMI의 동시 출력·EDID·분리/재연결은 256, 원격 영상 CPU·전달 지연 목표는 257의 별도 검증이다. 이번 결과로 그 항목들을 완료 처리하지 않는다.

지라 상태 변경·커밋·푸시는 하지 않았다. 완료 여부를 정리할 때는 지라의 과거 전체/상세 화면 설명을 현재 계기판·인포테인먼트 구성과 맞춰 읽어야 한다.
