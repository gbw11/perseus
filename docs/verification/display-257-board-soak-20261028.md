# 257 실보드 장시간 전송·성능 시험 (2026-10-28)

## 시험 범위

- 기준 커밋 `4bb91b7`, 브랜치 `feat/platform/S15P31E110-257-board-soak`.
- Raspberry Pi dom0의 실제 `/dev/fb1`을 사용하는 격리 Xorg·sandboxed Chromium·FFmpeg와 현재 platform의 표시 수집기·인증 MJPEG 서버를 사용한다.
- 한 물리 모니터에서 새 계기판 300초 + 새 인포테인먼트 300초를 순차 표시·수신한다. 각 화면 10분 또는 두 물리 출력의 동시 10분 시험이 아니다.
- 실제 X11 캡처 해상도 1824×984, 설정 5 FPS·JPEG quality 7이다. 초기 목표인 두 출력 1280×720 조건과 다르므로 정식 성능 수락과 구분한다.
- PC는 호스트 키를 고정한 SSH direct-tcpip를 통해 실제 HTTP multipart MJPEG를 연속 수신한다. 브라우저 표시 지연이나 지속 원격 디코드 측정으로 해석하지 않는다.
- 실제 Xen 실행 상태를 조회하지만 MQTT·실제 속도/배터리·미디어 송신기는 연결하지 않는다. 대기 화면의 JPEG가 같아도 각 multipart frame sequence가 증가하는지 확인한다.

## 계측

- PC: 프레임 순번·수신 단조 시각·JPEG 길이, 관측 FPS·프레임 도착 간격·1초 이상 공백·건너뛴 순번·JPEG payload 전송량.
- dom0: 약 1초 간격 `/proc` 계측. Python(수집기+송신기+진단 계측), FFmpeg, Chromium, Xorg를 구분해 CPU와 합산 RSS 기록. 첫 CPU 표본은 평균에서 제외한다.
- CPU 100%=1코어다. Python 내부 송신기와 수집기 CPU를 별도 분리하지 못하며, 짧게 생겼다 사라지는 하위 명령의 모든 CPU를 포착한다고 보장하지 않는다.
- RSS 합계에는 공유 페이지 중복이 있으므로 실제 고유 물리 메모리 사용량으로 해석하지 않는다. dom0 MemAvailable, thermal zone 온도, 인터페이스 RX/TX 카운터도 별도 저장한다.
- 인터페이스 전송량에는 SSH·API·동일 시간의 다른 트래픽이 포함된다. 두 출력 JPEG payload 합계나 순수 영상 wire overhead로 대입하지 않는다.
- 프레임 도착 간격은 종단 지연이 아니다. 동기화된 로컬/원격 표시 계측 없이 p95 500ms 통과를 주장하지 않는다.

## 안전·정리

실행 묶음과 웹·정책은 별도 시험 디렉터리에 배치한다. private mount/PID namespace, 최대 실행 시간, finally 정리 절차를 사용한다. 기존 Manager 서비스·SSH 정책·VM·펌웨어·부팅 자동 시작은 변경하지 않는다. 모니터가 EDID를 노출하지 않아 명시적 단일 framebuffer 진단 어댑터를 사용하며 `physical_verified=false`를 유지한다.

종료 후 원래 VT/픽셀 복원과 시험 프로세스·포트·마운트 정리, VM 상태를 별도 조회한다. 실제 결과는 시험 완료 후 아래에 추가한다.

### 화면 꺼짐 진단

별도 격리 Xorg에서 `xset q`로 아래 실제 설정을 확인했다.

- Screen Saver: prefer blanking=yes, timeout=600, cycle=600.
- DPMS: Enabled, standby/suspend/off 모두 600초.
- 같은 차량 화면에서 `xset s activate` 후 실제 캡처가 검은 화면으로 바뀌었고, `xset s reset` 후 정상 화면으로 복귀했다.

이는 무입력 절전/화면 보호 설정과 일치하는 재현이다. 원 장시간 시험에서 screensaver와 DPMS 중 어느 상태 전이가 먼저 일어났는지 별도 사건 로그로 구분하지 않았다. 운영 서비스에 화면 꺼짐 방지 설정을 적용하거나 수정 후 10분 재시험을 한 상태는 아니다.

### 성능 해석

현재 고해상도 조건에서 CPU 약 2.29코어는 목표 1코어보다 높다. Python에는 수집기와 진단 계측도 포함돼 있으므로 송신 전용 CPU라고 하지 않는다. 인코더 그룹 자체도 산술 평균 약 184%로 관측됐다. 화면이 검게 변한 구간이 있으므로 이 결과를 정상 콘텐츠 전체 10분의 성능 보장으로 사용하지 않는다.

FPS는 정확히 5가 아니며 payload는 한 출력씩의 값이다. 두 출력 동시 합계·720p 수락·종단 지연 p95는 미검증이다. 메모리 가용량과 RSS 표본은 있으나 10분 결과만으로 메모리 누수 유무를 확정하지 않는다.
