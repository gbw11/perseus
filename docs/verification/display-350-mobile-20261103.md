# 350 휴대폰 계기판·인포테인먼트 통합 화면

- 기준: `origin/platform` 99a3f0b, 작업 브랜치 `feat/platform/S15P31E110-350-mobile-display`.
- 목표 단말: 사용자 확인 갤럭시 S24. 실물 브라우저 가독성 확인은 아직 미수행.
- 보드에 접속하지 않았으며 VM·통신·서비스·HDMI 실행 설정을 변경하지 않았다.
- 이 기록은 로컬 제품 빌드와 합성 API 검증이다. USB 네트워크·실제 센서·최신 보드 배포의 검증으로 간주하지 않는다.

## 구현

`/display/mobile`에서 하나의 React 화면으로 계기판과 인포테인먼트를 함께 렌더링한다.
HDMI 영상을 캡처하거나 두 브라우저를 축소 합성하지 않는다. 가로는 두 영역을 나란히,
세로는 위아래로 배치한다. 좁은 화면·주소창·오류 알림으로 공간이 부족하면 세로 스크롤을
허용하며 가로 잘림을 방지한다. 안전 영역을 반영하고 확대를 막지 않는다.

- 속도·배터리: 현재 상태 계약에 센서 값이 없어 `—`와 수신 대기로 표시.
- 주행 모드: 기존 Gateway 상태의 선택 모드와 출력 허가를 구분. AUTO 선택만으로 구동 중이라 표시하지 않는다.
- 현재 구동 VM: 기존 수집기가 확정한 값을 사용. VM1 주 구동, VM2 백업·미러링, VM3 Debian을 구분한다.
- 게스트 콘텐츠: 기존 monitor-2 정책이 선택한 게스트를 재사용. 모바일의 새 선택/자동 승계 정책을 만들지 않는다.
- 네비게이션·음악: 아직 연결되지 않은 데이터는 대기. 임의 URL의 iframe·영상이나 가짜 주행 수치를 추가하지 않는다.
- 오류·복구 알림: 기존 정책 결정을 재사용. 연결 끊김 시 이전 정상 표시를 숨기고 재수신 후 복귀한다.

`useDisplay`의 기존 `/api/v1/display/presentation` 조회를 한 번만 사용한다.
MQTT 연결·Xen 조회·Gateway 조회를 브라우저에 새로 만들지 않는다.
휴대폰 페이지와 전용 CSS는 해당 경로에 접근할 때 지연 로딩해 기존 HDMI 진입 시 불필요한 로드를 줄인다.
주행/OS 표시 함수와 알림 컴포넌트는 HDMI와 공유한다.
모바일 페이지는 HDMI DOM ACK를 보내지 않고 물리 출력 준비를 주장하지 않는다.
기존 2개 outputs 스키마와 네이티브 HDMI 세션 코드는 유지한다.

서버의 모바일 HTML 경로는 기존 Bearer 또는 HttpOnly 표시 세션 인증을 요구한다.
서비스 토큰을 JS·쿼리·VITE 환경 변수에 넣지 않았다. 모바일의 초기 세션 발급·USB 인터페이스
접근 경로는 349번에서 다룬다. 350번에서 운영 서버를 외부 인터페이스로 개방하지 않는다.

## 프론트 디자인 반영

최신 `origin/frontend` c4495c1(2026-11-03)의 mock 대시보드를 별도 참조 폴더에서 렌더링해 확인했다.
기존 공통 `xenova` 브랜드 테마·로고·남색 카드·VM별 식별선·상태 점을 모바일 전용 TSX/CSS에 적용했다.
팀원의 관리자 화면·공통 토큰·라우팅 파일을 가져와 덮어쓰지 않았다.
최종 증거 이미지는 이 디자인을 반영한 제품 빌드로 갱신했다.

| 검사 | 결과 |

| 표시 프론트 테스트 | 37개 통과. 기존 HDMI 회귀 + 모바일 모드 선택/허가·단절·복귀·지연·오류·게스트 선택 |
| 서버 정책·인증, Gateway, 네이티브 HDMI 세션 테스트 | 63개 통과 |
| 제품 빌드 | TypeScript + Vite 통과 |
| 변경 TS/TSX ESLint | 오류 없음. 기존 main.tsx Fast Refresh 경고 3건 |
| 실제 제품 빌드 Chrome 시각 검사 | 10개 사례, JS 오류·가로 넘침·쓰기 요청 없음 |

Chrome 사례는 915×412, 412×915, 360×640, 740×360, 320×568 및
S24 검토용 CSS viewport 360×780·780×360·주소창 축소 780×300을 사용했다.
이는 실제 S24가 보고한 viewport 수치가 아니라 반응형 검토 조건이다.
780×360과 740×360의 정상/준비 화면은 세로 스크롤 없이 표시된다.
360×780·더 좁은 세로 화면 및 높이 300 가로에서는 필요한 세로 스크롤을 허용한다.
오류와 연결 단절 화면도 별도 검사했으며 HTTP 오류 후 자동 재수신 복귀를 확인했다.

## 재현

```powershell
# 작업 브랜치의 frontend 폴더에서
npm ci --offline --ignore-scripts --no-audit --no-fund
npm test -- apps/vm-screens/src/display
npm run build -w @xenova/vm-screens

# 저장소 루트에서, Playwright가 있는 로컬 Python 사용
python platform/services/display/router/tests/probe_mobile_browser.py

# 선택: 동일 Wi-Fi에서 실물 폰 UI만 검토. PC의 실제 사설 IP를 지정한다.
python platform/services/display/router/tests/preview_mobile.py --host <PC의_IP> --port 18750
```

미리보기는 빌드 산출물과 합성 데이터만 제공하고 30분 뒤 종료한다. 기본 주소는 loopback이며
특정 PC 사설 IP를 명시해야 다른 단말에서 접근할 수 있다. 방화벽을 자동 변경하지 않는다.
운영용 인증/USB 서버가 아니며 Git에는 비밀정보가 없는 시험 데이터만 포함한다.

## 남은 확인과 경계

- **350**: 실물 S24에서 Chrome 가로·세로, 주소창, 글자 크기, 확대·스크롤을 확인해야 최종 수락 가능.
  사용자는 현재 실물 접속 확인이 불가능하다고 답했다. 완료로 변경하지 않는다.
- **349**: USB 드라이버·IP·접근 인증과 실제 상태 연결. 이번 미리보기는 이를 검증하지 않는다.
- **351**: HDMI/휴대폰 옵션 선택과 실행 서비스 전환. 이번에 HDMI 서비스를 중지/변경하지 않았다.
- **352**: 실제 유선 단절·복귀·성능 검증. 브라우저 모의 HTTP 단절을 USB 실물 시험으로 대체하지 않는다.
- 외부 관리자 웹 메뉴/라우팅과 차량 조작은 변경하지 않는다.
