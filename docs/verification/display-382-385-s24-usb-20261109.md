# 382·385 Galaxy S24 USB 테더링 접속과 휴대폰 화면 표시 — 실보드 (2026-11-09)

관련: [S15P31E110-382](https://ssafy.atlassian.net/browse/S15P31E110-382), [S15P31E110-385](https://ssafy.atlassian.net/browse/S15P31E110-385). 보드에 손으로 넣은 설정은 [BUILD-CHECKLIST.md](../../platform/services/display/router/deploy/guest-display/BUILD-CHECKLIST.md) §4에 정리했다.

## 환경

- 보드: Raspberry Pi 4, Xen dom0, 커널 `6.18.33-v8`. 11-05 이미지에 위 §4의 수동 설정을 더한 상태다.
- 휴대폰: Galaxy S24. USB 테더링(RNDIS)을 썼다. Android·One UI 버전은 기록하지 못했다.
- 연결: USB-C → USB-A 데이터 케이블. 보드의 검은 USB 2.0 포트를 썼다(파란 USB 3.0 포트는 2.4GHz Wi-Fi 간섭을 피하려고 쓰지 않았다).
- 보드 네트워크: wlan0 `192.168.30.88/24`가 기본 경로이고, Tailscale도 켜져 있다.

## 382 — USB 인식·드라이버·IP

- **드라이버:** `rndis_host`, `cdc_ether`, `cdc_ncm`이 모듈로 들어 있다. 꽂으면 자동으로 올라와 `usb0`(`SAMSUNG_Android`, `04e8:6863`)으로 잡힌다.
- **첫 케이블(포트 1-1.4):** 붙자마자 약 0.1초 만에 끊기고, 약 1초 뒤 다시 붙기를 반복했다. 몇 분 사이 장치 번호가 37에서 81까지 올라갔고, IP는 받지 못했다.
- **케이블을 바꾼 뒤(포트 1-1.3):** 20초 동안 다시 붙은 횟수가 0이다. 원인은 케이블로 판단한다.
- **주소:**
  - 휴대폰은 두 번 모두 `10.104.83.148`이었다.
  - 보드 `usb0`은 `10.104.83.37/24`였다가, 다시 연결한 뒤 `10.104.83.17/24`가 됐다.
  - 즉 보드 주소는 연결할 때마다 바뀔 수 있다.
- 휴대폰의 "USB 제어 기기" 설정은 바꿀 수 없었지만, 테더링은 동작했다.

### 기본 경로 문제와 조치

- **문제:** 이미지의 `80-wired.network`(Type=ether, DHCP=yes)가 usb0에 적용됐다.
  - 휴대폰 기본 경로가 **metric 10**으로 잡혀서 wlan0(600)보다 우선이 됐다(11:31 확인).
  - 그동안 보드의 인터넷·Tailscale 통신이 휴대폰을 거쳤다.
- **조치:** `/etc/systemd/network/20-xenova-usb-phone.network`를 추가했다.
  - USB 테더링 드라이버 링크는 IP만 받고, gateway·routes·DNS는 받지 않는다.
  - 재부팅과 재연결 뒤에도 기본 경로가 wlan0으로 유지되는 것을 확인했다.

## 385 — 실제 USB 주소의 접속 서비스·인증·화면

1. **접속 설정:** `/etc/xenova/display-mobile.json`(root 0600)에 `usb0`, 휴대폰 IP, 포트 8084를 넣었다.
2. **접속 서비스:** `xenova-display-mobile`을 먼저 시작했고, 24초 만에 준비됐다.
   - 보드 부하 때문에 import가 느리다.
   - `display_mode`는 15초만 기다리므로 미리 시작했다.
3. **수신 주소:** `10.104.83.17:8084`에만 수신한다(usb0에 bind).
4. **연결과 표시:** 휴대폰 브라우저로 `http://10.104.83.17:8084/display/mobile`을 열었다. 6자리 연결번호로 11:58:35에 연결됐다.
   - **사용자가 휴대폰에 차량 화면이 뜬 것을 확인했다.**
   - 연결번호는 기록하지 않았다.
5. **휴대폰 모드 전환:** `display_mode mobile`이 처음에는 `DISPLAY_MODE_CHECK_FAILED`로 멈췄다.
   - 원인: 이미지에 HDMI 모드 guard `60-display-mode.conf`가 없어서 `FileNotFoundError`가 났다.
   - guard를 손으로 넣은 뒤에는 `applied: true`, `selected: mobile`로 바뀌었다.
6. **기존 상태 유지:** HDMI inactive, 기본 경로 wlan0, VM과 서비스는 바꾸지 않았다.
