# 382·385 Galaxy S24 USB 테더링 접속과 휴대폰 화면 표시 — 실보드 (2026-11-09)

관련: [S15P31E110-382](https://ssafy.atlassian.net/browse/S15P31E110-382), [S15P31E110-385](https://ssafy.atlassian.net/browse/S15P31E110-385). 보드에 손으로 넣은 설정은 [BUILD-CHECKLIST.md](../../platform/services/display/router/deploy/guest-display/BUILD-CHECKLIST.md) §4에 정리했다.

## 환경

- 보드
  - Raspberry Pi 4 Model B Rev 1.5, Xen dom0, 커널 `6.18.33-v8`
  - 이미지는 `Xenova 6.0.4 (wrynose)`(11-05 배포)에 위 §4의 수동 설정을 더한 상태다.
- 휴대폰: Galaxy S24, **One UI 8.5, Android 16**, 화면 6.2인치(155 mm). USB 테더링(RNDIS)을 썼다.
- 연결
  - 케이블: USB-C → USB-A 데이터 케이블
  - 포트: 보드의 검은 USB 2.0 포트(`1-1.3`, 480 Mb/s). 파란 USB 3.0 포트는 2.4 GHz Wi-Fi 간섭을 피하려고 쓰지 않았다.
- 전원
  - 휴대폰은 보드 포트에 500 mA를 요청한다(`bMaxPower`).
  - 이번 부팅의 dmesg에는 전압 저하 기록이 없다. 다만 이 이미지에는 Pi 전압 감시 드라이버(`raspberrypi-hwmon`)와 `vcgencmd`가 없어서, 기록이 없다는 것만으로 전압이 정상이라고 확정할 수는 없다.
  - 보드 전원 어댑터 사양은 기록하지 않았다.
  - SoC 온도는 41.9 °C였다(14:18).
- 보드 네트워크: wlan0 `192.168.30.88/24`가 기본 경로이고, Tailscale도 켜져 있다.

## 382 — USB 인식·드라이버·IP

- **드라이버:** `rndis_host`, `cdc_ether`, `cdc_ncm`이 모듈로 들어 있다. 꽂으면 자동으로 올라와 `usb0`(`SAMSUNG_Android`, `04e8:6863`)으로 잡힌다.
- **첫 케이블(포트 1-1.4):** 붙자마자 약 0.1초 만에 끊기고, 약 1초 뒤 다시 붙기를 반복했다. 몇 분 사이 장치 번호가 37에서 81까지 올라갔고, IP는 받지 못했다.
- **케이블을 바꾼 뒤(포트 1-1.3):** 20초 동안 다시 붙은 횟수가 0이다. 원인은 케이블로 판단한다.
- **재연결 주소 규칙**(4번 연결해서 확인)

  | 연결 | 보드 `usb0` | 휴대폰 |
  |---|---|---|
  | 1 (케이블 교체 뒤, 11:31 확인) | `10.104.83.37/24` | `10.104.83.148` |
  | 2 (11:45 재부팅 뒤) | `10.104.83.17/24` | `10.104.83.148` |
  | 3 (다시 꽂기 시험) | `10.104.83.109/24` | `10.104.83.148` |
  | 4 (12:55 재부팅 뒤, 14:18) | `10.104.83.77/24`(ifindex 9) | `10.104.83.148` |

  - 휴대폰은 서브넷 `10.104.83.0/24`의 `.148`에서 바뀌지 않았다. DHCP 서버와 게이트웨이 역할을 한다.
  - **보드 주소는 연결할 때마다 새로 받는다.** 그래서 접속 URL도 연결할 때마다 바뀐다.
  - 다시 꽂으면 커널에 새 `usb0` 장치(새 ifindex)가 생긴다. 설치된 접속 서비스는 처음 장치에 묶여 있어서 재시작해야 했다. 서비스가 연결 변화를 따라가도록 MR !512(S15P31E110-393)에서 고쳤다.
  - 테더링을 켜면 휴대폰이 USB 모드를 바꾸면서 한 번 다시 연결된다(14:17 `device number 3 → 4`). 정상 동작이다.
- 휴대폰의 "USB 제어 기기" 설정은 바꿀 수 없었지만, 테더링은 동작했다.

### 기본 경로 문제와 조치

- **문제:** 이미지의 `80-wired.network`(Type=ether, DHCP=yes)가 usb0에 적용됐다.
  - 휴대폰 기본 경로가 **metric 10**으로 잡혀서 wlan0(600)보다 우선이 됐다(11:31 확인).
  - 그동안 보드의 인터넷·Tailscale 통신이 휴대폰을 거쳤다.
- **조치:** `/etc/systemd/network/20-xenova-usb-phone.network`를 추가했다.
  - USB 테더링 드라이버 링크는 IP만 받고, gateway·routes·DNS는 받지 않는다.
  - 재부팅과 재연결 뒤에도 기본 경로가 wlan0으로 유지되는 것을 확인했다.

## 385 — 실제 USB 주소의 접속 서비스·인증·화면

1. **접속 설정:** `/etc/xenova/display-mobile.json`(root 0600)에 `usb0`, 휴대폰 IP, 포트 8084를 넣었다.
2. **접속 서비스:** `xenova-display-mobile`을 먼저 시작했고, 24초 만에 준비됐다.
   - 보드 부하 때문에 import가 느리다.
   - `display_mode`는 15초만 기다리므로 미리 시작했다.
3. **수신 주소:** `10.104.83.17:8084`에만 수신한다(usb0에 bind).
4. **연결과 표시:** 휴대폰 브라우저로 `http://10.104.83.17:8084/display/mobile`을 열었다. 6자리 연결번호로 11:58:35에 연결됐다.
   - **사용자가 휴대폰에 차량 화면이 뜬 것을 확인했다.**
   - 연결번호는 기록하지 않았다.
5. **휴대폰 모드 전환:** `display_mode mobile`이 처음에는 `DISPLAY_MODE_CHECK_FAILED`로 멈췄다.
   - 원인: 이미지에 HDMI 모드 guard `60-display-mode.conf`가 없어서 `FileNotFoundError`가 났다.
   - guard를 손으로 넣은 뒤에는 `applied: true`, `selected: mobile`로 바뀌었다.
6. **기존 상태 유지:** HDMI inactive, 기본 경로 wlan0, VM과 서비스는 바꾸지 않았다.

### 미인증 접근 거부 (14:19, 연결 4)

접속 서비스를 `10.104.83.77%usb0:8084`에서 시작했다. 준비까지 20초 걸렸고 설정은 바꾸지 않았다. 휴대폰이 아닌 곳에서 요청했다.

| 요청 | 결과 |
|---|---|
| 보드 자신 → `/display/mobile`, `/connect`, presentation API | 403 `PHONE_LINK_REQUIRED` |
| 보드 자신 → `POST /connect`(번호 추측) | 403. 연결번호는 소모되지 않음 |
| 보드 자신, `X-Forwarded-For: <휴대폰 IP>` | 403 |
| wlan0 `192.168.30.88:8084`, loopback, Tailscale `100.108.226.65:8084` | 연결 거부(수신하지 않음) |

- feed는 계속 active였다. HDMI와 기본 경로(wlan0)는 바뀌지 않았다.

### 휴대폰 연결 (14:2x, 연결 4)

- **인증 전 화면:** 보드 주소가 `.77`로 바뀌어서 휴대폰 브라우저에는 이 주소의 cookie가 없었다. 일반 탭으로 `http://10.104.83.77:8084/display/mobile`을 열자 차량 화면이 아니라 **번호 입력 화면**이 나왔다. 인증하지 않은 휴대폰에는 화면을 보여 주지 않는다는 뜻이다.
- **시크릿 탭:** 페이지가 열리지 않았다. 원인은 확인하지 않았다. 브라우저의 시크릿 모드 HTTPS 우선 설정일 가능성이 있다. 인증 전 화면은 위의 일반 탭으로 확인했다.
- **연결:** 6자리 번호로 14:24:50~14:26:21 사이에 연결됐다(번호 사용 처리 확인). 번호는 기록하지 않았다.
- **데이터 수신:** 연결된 뒤 휴대폰(`.148`)이 연결 1개를 유지했다. 14:26:53~14:27:14에 보드가 보낸 양은 10초마다 약 70~80 KB였고, 휴대폰 요청은 약 2.5 KB였다. 즉 presentation을 계속 받아 가고 있다.
