# 시뮬레이터 시연 시나리오 (Plan B)

실차(RC카·ESP32·젯슨·카메라)가 데모까지 준비되지 않을 때를 대비해, **차와 카메라만 화면 속 시뮬레이터로 바꾸고 보드·VM·게이트웨이·관제는 그대로 둔 채** [RC카 시나리오](scenario-rc-car.md)를 시연한다.
보여 주려는 것은 같다. **주행 중인 VM 이 죽어도 차가 안전하게 계속 가거나 멈추고, 죽은 VM 은 자동으로 돌아온다.**

> 상태: 초안 (2026-10-22, S15P31E110-265). 에픽 S15P31E110-17, 이슈 -259 ~ -265, -267, -268.
> 흐름·모드·장애 규칙은 [RC카 시나리오](scenario-rc-car.md) §3·§4 와 [MQTT 계약](contracts/mqtt-contract-v1.md) §5 를 그대로 따른다. 이 문서는 **무엇을 시뮬레이터로 바꾸는지**와 시연 방법만 적는다.

## 1. 왜

- 장비(차체·모터 드라이버·D435f·젯슨) 도착에 일주일 이상 걸려 10/26 중간 점검·10/27 통합 데모 전에 실차 주행을 맞추기 어렵다.
- 실차가 와도 주행이 불안정하면 핵심 장면(D3 인계·D4 복구)을 못 보여 줄 수 있다.
- RPi4 + Xen 보드와 VM 기동은 이미 확인됐다. 그래서 **보드는 실제로 쓰고, 차와 눈만 노트북의 시뮬레이터로 바꾼다.**

원칙: **시뮬레이터 때문에 앱·게이트웨이·백엔드·화면 코드를 따로 만들지 않는다.** 실차가 붙으면 시뮬레이터 자리에 ESP32, 인지 대역 자리에 젯슨을 꽂으면 Plan A 가 된다.

## 2. 구성

| | Plan A (실차) | Plan B (시뮬레이터) |
| --- | --- | --- |
| 보드 | RPi4 + Xen | 같음 |
| VM | 자율·수동 Zephyr + 인터랙션 Debian | 같음 |
| dom0 | 브로커·게이트웨이·복구 서비스·표시 서비스 | 같음 |
| 차 | ESP32 + RC카 (USB 시리얼) | **시뮬레이터** (노트북, 이더넷 TCP 로 같은 프레임) |
| 인지 | D435f + 젯슨 | **인지 대역** (노트북) |
| 관객이 차를 보는 곳 | 실제 차 | **시뮬레이터 화면** (§4) |

```text
 ┌──────────────── RPi4 + Xen (실제) ────────────────┐            ┌────────── 노트북 ──────────┐
 │ 자율 VM ─┐                                         │            │                           │
 │ 수동 VM ─┴ drive.command ─▶ 게이트웨이 ── 프레임 ──┼── TCP ───▶ │ 시뮬레이터 (ESP32 + 차체)   │
 │                              ▲  │ vehicle.status   │ ◀─ 상태 ── │   │ 차 위치·트랙·장애물      │
 │ 인터랙션 VM                   │  ▼                  │            │   ▼                       │
 │                     Mosquitto ◀── perception.result ┼────────────┤ 인지 대역 (젯슨 자리)      │
 │                              │                     │            │   └ 합성 카메라 영상       │
 │ 백엔드 → 관리 콘솔·모니터 2대 (시뮬레이터 화면 포함)  │            └───────────────────────────┘
 └────────────────────────────────────────────────────┘
```

- 시뮬레이터는 **ESP32 자리**(게이트웨이 시리얼 뒤)에 들어간다 (-260). 게이트웨이는 시리얼 대신 TCP 로 같은 프레임(COBS + CRC, -241)을 보낸다. `vehicle.status` 는 Plan A 와 똑같이 게이트웨이만 발행한다.
- 인지 대역은 **젯슨 자리**에 들어간다 (-156 확장). 시뮬레이터가 알려 주는 차 위치·트랙·장애물로 `perception.result`(차선 오프셋·방향 오차·장애물 거리·정지 필요)를 계산해 15 Hz 로 낸다. 자율주행 앱이 낸 조향이 실제로 차를 트랙 위에 붙잡아 두는 **닫힌 고리**가 된다.

## 3. 시뮬레이터가 흉내 내는 것

| 실차 | 시뮬레이터 | 근거 |
| --- | --- | --- |
| ESP32 와치독 300 ms | 프레임 300 ms 끊기면 정지 + `flags.watchdog` | 계약 §5.5, -241 |
| 모터·조향 | 자전거 모델, 가속 2 m/s², 조향 속도 제한 | -47 |
| ToF 장애물 | 차 앞 감지 거리 안에 장애물 → `flags.obstacle` + 전진 차단 | -47 |
| E-stop 버튼 | 관리 콘솔 [E-stop] (시뮬레이터 터미널 `e` 도 남김) | -47 |
| 엔코더 속도 | 모델 속도 그대로 | — |
| 트랙·위치 | **실차에 없는 값.** 시뮬레이터 전용 토픽 `xenova/v1/sim/pose`(20 Hz)·`sim/world`(retained) | -261 |
| D435f 영상 | 인지 대역이 시뮬레이터 장면을 그린 합성 MJPEG (`raw.mjpg` 자리) | -263, camera-stream-v1 |

## 4. 화면

```text
 모니터 1 (3분할)                                                  모니터 2 (상세)
┌──────────────────┬──────────────────┬──────────────────────┐   ┌──────────────────────────┐
│ 자율주행 VM       │ 수동주행 VM       │ 시뮬레이터            │   │ 모니터 1 의 칸 중 관리     │
│ 모드·세대·상태 배지│ 대기 / 운전 중    │ 트랙·차·장애물 (탑뷰) │   │ 콘솔에서 고른 1개를 크게   │
│ 인지: 장애물 0.5 m│ 키 입력 ↑ ←      │ 모드 색, 3·2·1        │──▶│ (보통은 시뮬레이터)        │
│ 판단: 정지        │ 인계까지 82 ms   │ 인터랙션 알림 띠      │   │                          │
└──────────────────┴──────────────────┴──────────────────────┘   └──────────────────────────┘
```

| 화면 | 내용 | Plan A 와 다른 점 |
| --- | --- | --- |
| **시뮬레이터 화면** (-262, 새로) | 트랙을 위에서 내려다본 그림(탑뷰) 위에 차(위치·방향)·장애물·감지 범위, 모드 색, 속도·조향, 3·2·1 카운트다운 | Plan A 의 "실제 차" 자리. 관객이 차 움직임을 여기서 본다 |
| 모니터 1 (3분할) | 자율주행 · 수동주행 · **시뮬레이터** | 세 번째 칸이 인터랙션 VM 대신 시뮬레이터 |
| 모니터 2 (상세) | Plan A 처럼 관리 콘솔에서 고른 화면 1개 (자율주행 / 수동주행 / 시뮬레이터 / 인터랙션) | 선택지에 시뮬레이터 추가 |
| 관리 콘솔 | Plan A 와 같음 (VM 목록·장애 주입·재개) + **트랙 조작**: 장애물 놓기·옮기기·치우기, E-stop, 차 밀기 | 트랙 조작 추가 (§4-1) |
| 카메라 | 합성 영상, 인터랙션 VM 화면·콘솔에서 | 영상이 그림 |

- 인터랙션 VM 은 그대로 돈다 (알림·재개 요청·카메라 AI). 모니터 1 칸에서 빠지는 대신 시뮬레이터 칸 아래 **알림 띠**에 그 VM 이 낸 알림을 보이고, 상세는 모니터 2 에서 고른다. 그 VM 이 죽으면 알림 띠가 "인터랙션 VM 응답 없음"으로 바뀌고 차는 계속 달린다 (D8 격리).
- 시뮬레이터 화면 데이터는 백엔드 중계로 받는다. 화면은 브로커에 직접 붙지 않는다 (MQTT 계약 D2 와 같은 원칙).

### 4-1. 정해진 코스가 아니라 자율주행이라는 증거

1. **아무 때나, 아무 곳에** 장애물을 놓는다. 심사위원에게 위치를 고르게 한다.
2. 자율주행 칸이 **자기가 본 인지 값과 판단**을 실시간으로 보인다 (장애물 거리 → 감속 → 정지, 차선 오프셋 → 조향).
3. **차 밀기**: 콘솔에서 차를 옆으로 30 cm 옮기면 자율주행이 스스로 차선으로 돌아온다.

## 5. 데모 순서

[RC카 시나리오](scenario-rc-car.md) §6 의 D1 ~ D8 을 그대로 따르고, 차 움직임은 시뮬레이터 화면에서 본다.

| # | 조작 | 시뮬레이터 화면에서 보이는 것 | 측정 |
| --- | --- | --- | --- |
| D1 | 세 VM 기동, 자율 출발 | 차가 트랙을 따라 돈다 (AUTO 색) | 출발까지 시간 |
| D1-1 | 콘솔에서 트랙에 장애물 놓기 → 치우기 | 장애물 앞에서 멈추고, 치우면 다시 출발. 인터랙션 알림 | 정지 거리 |
| D2 | 인터랙션 VM 에 CPU 부하 | 차는 그대로 돈다 (격리) | 자율 명령 주기 지터 |
| D3 | **자율 VM 강제 종료** | 100 ms 안에 MANUAL 색, 차가 멈춤 → 운영자가 키로 운전 | 전환 시간, 전환 중 이동 거리 |
| D4 | 자동 복구 → 재개 | 복구 중 → AUTO_READY → [재개] → 3·2·1 → 다시 자율 | VM 재시작 시간, 재개 가능까지 시간 |
| D5 | 자율·수동 둘 다 종료 | SAFE_STOP 색, 바로 정지 | 정지까지 시간 |
| D6 | 게이트웨이 종료 | 시뮬레이터 와치독 300 ms 정지, 사람이 확인해야 재출발 | 정지까지 시간 |
| D7 | E-stop | 정지 표시 | — |
| D8 | 인터랙션 VM 종료 | 알림 띠가 "응답 없음", 카메라만 멈추고 차는 계속 | 명령 주기 변화 없음 |
| D9 | 차 밀기 (콘솔) | 차가 옆으로 밀렸다가 스스로 차선으로 돌아옴 (§4-1) | 복귀 시간 |

핵심은 D3·D4. 시간이 부족하면 D1 → D1-1 → D3 → D4 → D5.

측정값 중 VM·게이트웨이 쪽(전환 시간, 재시작 시간, 명령 주기)은 **실보드 값**이다. 차 쪽(이동 거리, 와치독 정지)은 **모델 값**이라고 밝힌다.

## 6. 보여 줄 수 있는 것 / 없는 것

| | Plan A | Plan B |
| --- | --- | --- |
| Xen 위 VM 격리 (D2·D8) | ✅ | ✅ |
| VM 장애 → 인계 → 자동 복구 → 재개 | ✅ | ✅ |
| 실시간 OS(Zephyr) 주행 앱 | ✅ | ✅ |
| 하드웨어 안전 (ESP32 와치독·E-stop) | ✅ 실제 | 모델 |
| 카메라 인지 (D435f + 젯슨) | ✅ 실제 | 대역 |

발표 멘트: 처음에 **"차와 카메라만 시뮬레이터로 바꿨고, 보드·VM·게이트웨이·관제는 실차와 같은 코드가 실제로 돈다"** 고 밝힌다.

## 7. 결정 필요

| # | 항목 | 결정 |
| --- | --- | --- |
| P1 | 시뮬레이터 화면 위치 | **모니터 1 세 번째 칸**(인터랙션 대신), 모니터 2 는 고른 1개 (2026-10-22) |
| P2 | 장애물·E-stop 조작 위치 | **관리 콘솔** 트랙 조작 (놓기·옮기기·치우기, E-stop, 차 밀기) (2026-10-22) |
| P3 | 인지 대역 입력 | **시뮬레이터 속 차의 실제 위치·장애물로 계산** (닫힌 고리). 미리 짠 각본은 쓰지 않는다 — 장애물·차 밀기에 반응하지 못해 "정해진 코스"가 되기 때문 (2026-10-22) |
| P4 | 트랙 모양 | **타원** 약 6 m × 3 m, 차선 폭 0.4 m. 실차 트랙도 같은 모양으로 맞춘다 (2026-10-22) |
| P5 | Plan A → B 판단 기준·시점 (-265) | 아래 §7-1 (2026-10-22) |

### 7-1. Plan A → B 판단

| 시점 | 확인 | 결과 |
| --- | --- | --- |
| 10/25(일) 리허설 | 실차로 D1(자율 주행)·D3(인계) | 3번 중 2번 이상 성공하면 A 유지, 아니면 10/26 중간 점검은 B |
| 10/25 전 | 장비가 도착하지 않음 | 10/26 은 처음부터 B 로 확정 |
| 10/27(화) 아침 | 실차 D3 1번 | 성공하면 A, 실패하면 B |

- 정하는 사람: 팀장. 결정은 MM 에 공유한다.
- 데모 도중에는 A 가 실패했을 때 B 로 넘어가는 것만 허용한다. 그래서 A 로 가더라도 노트북의 시뮬레이터·인지 대역은 **미리 띄워 둔다** (게이트웨이 연결만 TCP 로 바꾸면 된다).
