# 화면 정의서

웹(관리 콘솔)과 모니터 2대에 **어떤 화면이 들어가고, 각 화면이 무엇을 보여 주고 무엇을 조작하는지**를 정한다.
디자인(스티치)은 이 문서의 화면 목록·정보·동작을 기준으로 만들고, 구현은 디자인을 따른다.

> 상태: 초안 (2026-10-20, S15P31E110-50). Low-Fi 정의이며 모양·색은 디자인에서 정한다.
> 근거: 노션 요구사항 명세 "관리 UI·화면"(UI-01~09, DS-01~02), [RC카 시나리오](../scenario-rc-car.md) §4·§5,
> [MQTT 계약](../contracts/mqtt-contract-v1.md), [VM 관리 API 계약](../contracts/vm-api-contract-v1.md), 노션 API 명세(REST·WS).

## 1. 기기와 역할

| 기기 | 누가 보나 | 역할 | 입력 |
| --- | --- | --- | --- |
| **웹 — 관리 콘솔** (노트북 브라우저) | 운영자 | 시연을 **조작**하고 VM 을 **관리**한다 | 마우스·키보드 |
| **모니터 1** (RPi4 HDMI, 27인치) | 관람자 | VM 3개 **전체 상황** (3분할) | 없음 |
| **모니터 2** (RPi4 HDMI) | 관람자 | 운영자가 고른 VM 1개 **상세** | 없음 |

- 모니터는 보여 주기만 한다. 터치가 없으므로 **모든 조작은 웹에서** 한다 (수동주행 키 입력 포함).
- 모니터 화면은 웹 페이지로 만들고 dom0 표시 서비스가 키오스크 브라우저로 띄운다. 어느 모니터에 무엇을 띄울지는 웹의 화면 라우터(DS-01)가 정한다.
- 27인치가 모니터 1·2 중 어느 쪽인지는 설치 때 정한다 (§7 Q1). 큰 쪽을 3분할(모니터 1)로 쓰는 것을 제안한다.

```text
            ┌──────────── 웹 (운영자) ────────────┐
            │ 대시보드 · VM · 자원 · 시연 제어 · 이벤트 │
            └──────┬───────────────┬──────────────┘
          REST·WS  │               │ 화면 배치 (REST-24)
                   ▼               ▼
        Spring 백엔드 ──WS-04──▶ dom0 표시 서비스 ──HDMI──▶ 모니터 1 (3분할) / 모니터 2 (상세)
                   │                                       ▲
                   └── MQTT (주행 상태·이벤트) ─────────────┘
```

## 3. 공통 표시 규칙

| 규칙 | 내용 | 근거 |
| --- | --- | --- |
| 상태 배지 4종 | 정상(초록) · 장애(빨강) · 복구 중(노랑, 경과 시간) · 정지(회색). 화면마다 다른 말을 쓰지 않는다 | RC카 시나리오 §4.3 |
| 주행 모드 4종 | 자율주행 `AUTO` · 수동주행 `MANUAL` · 재개 가능 `AUTO_READY` · 안전 정지 `SAFE_STOP` | MQTT 계약 §5.2 |
| 앱 역할색 | 자율주행 · 수동주행 · 인터랙션을 색으로 구분 (모든 화면 같은 색) | |
| VM 식별 | Linux 는 배포판(Debian·Ubuntu), Zephyr 는 **같은 OS 이므로 이름·역할로 구분** ("자율주행 VM", "수동주행 VM") | DS-02 |
| 준비 ≠ 제어권 | 예비 VM 이 "준비됨" 인 것과 "차량 제어 중" 인 것을 다른 표시로 쓴다 | UI-09 |
| 의도적 정지 | 콘솔에서 끈 VM 은 장애가 아니라 '정지' 로 표시, 자동 재시작하지 않음 | RC-04, 시나리오 §4.3 |
| 시각 | 경과 시간("3초 전")은 화면 시계 기준. 보드 간 시각을 비교해 판정하지 않는다 | MQTT 계약 §1 |

### W-02 대시보드 — 주행 통합 상태 (UI-09)

데모 중 운영자가 계속 띄워 두는 화면. **한 화면에서 "지금 누가 차를 몰고 있고, 넘길 준비가 됐는지"** 가 보여야 한다.

```text
┌ 주행 모드: 자율주행 (AUTO · gen 4)   활성: 자율주행 VM   안전: 구동 허용 ─────────────┐
├──────────────────────┬──────────────────────┬──────────────────────────────────┤
│ 자율주행 VM  [정상]   │ 수동주행 VM  [정상]   │ 인터랙션 VM  [정상]              │
│ ▶ 차량 제어 중        │ 예비 — 준비됨         │ 알림 표시 중                     │
│ 명령 50 Hz           │ 명령 50 Hz (v=0)     │ 에이전트 연결됨                  │
├──────────────────────┴──────────────────────┴──────────────────────────────────┤
│ 차량: 0.50 m/s · 조향 +0.07 rad · 비상정지 버튼 안 눌림 · 명령 끊김 정지 아님 · 장애물 없음 │
│ 인지(젯슨): 유효 · 15 Hz · 마지막 수신 0.1초 전                                     │
├────────────────────────────────────────────────────────────────────────────────┤
│ 최근 이벤트 5건  (→ 이벤트 타임라인)                                                │
└────────────────────────────────────────────────────────────────────────────────┘
```

| 독립 항목 (UI-09) | 값 | 데이터 |
| --- | --- | --- |
| 주행 모드 | AUTO·MANUAL·AUTO_READY·SAFE_STOP + 세대 | `vehicle.control` (MQTT-09) |
| 활성 VM | 차량 명령을 실제로 전달받는 앱 | `vehicle.control.active_app` |
| 예비 VM 준비 | 수동주행 명령 신선 여부 (100 ms) | `drive.command` 수신 (MQTT-06) |
| 안전·구동 허용 | 비상정지 버튼(E-stop), 명령 끊김 정지(ESP32 와치독 300 ms), 근거리 장애물 — 코드 대신 뜻을 풀어 쓴다 | `vehicle.status.flags` (MQTT-10) |
| 인지 유효성 | 젯슨 결과 수신 주기·마지막 수신 | `perception.result` (MQTT-06) |
| VM 상태 | 도메인 상태, 에이전트(Linux) | `GET /api/v1/vms` |

**시뮬레이터 구성 (데모 기본, [시뮬레이터 시연 시나리오](../scenario-simulator.md) §4)**: 세 번째 카드가 인터랙션 대신 **시뮬레이터**로 바뀐다 — 트랙 탑뷰(차·장애물·감지 범위, 차 색 = 제어 중인 앱), 위치·속도·장애물 수·트랙 revision, 네비게이션 VM 상태 한 줄. MQTT 계약 v1.4 실제 서킷이면 탑뷰가 실제 서킷 그림(잔디·흙·벽·관중석·나무)이 되고, **트랙 고르기**(레드불링·몬차, REST-36)·**다시 출발**(출발 신호 처음부터, REST-37) 버튼과 km/h·출발 신호·랩 시간이 나온다. 시뮬레이터 위치(WS-06)가 1초 안에 왔을 때만 바뀌고, 끊기면 원래 인터랙션 카드로 돌아온다 (화면 배치 계약 v1.1 §5.6). 나머지 카드·띠는 그대로다.

### W-07 시연 제어 (UI-08, DS-01, 수동주행 입력)

**시뮬레이터 구성 — 트랙 조작 카드** (-267, MQTT 계약 v1.4, 격리 시연 카드 아래): 지도 위쪽(지도 밖)에 장애물 그림(콘·박스·타이어, 실제 폭)이 있고 **끌어다 지도에 놓으면** 그 자리에 놓인다 (끄는 동안 놓일 자리 점선 원). 그림을 고른 뒤 지도를 눌러도 놓이고, 장애물을 끌면 옮기고, 두 번 누르면 치운다. 차가 지나가지 못하는 자리는 시뮬레이터가 거부하고(MQTT-18) 이유를 알림으로 띄우며 그 자리에 빨간 X. 오른쪽: 놓을 장애물 종류(실제 폭), 무작위 3개·모두 치우기, 출발 상태·지난/최고 랩·속도와 [다시 출발], 차 밀기(왼쪽·오른쪽 15 m)·E-stop, 트랙 위 장애물 목록(차 앞 거리, 하나씩 치우기). 머리에 트랙 고르기(레드불링·몬차). mock 은 운영자가 한 번 조작하면 시연용 자동 재배치를 멈춘다.

데모 진행자가 쓰는 화면. 세 영역을 한 화면에 둔다.

```text
┌ 화면 배치 (DS-01) ─────────────────────────┬ 격리 시연 (UI-08) ─────────────────────────┐
│ 모니터 1: [3분할 ▼]                          │ 대상 VM: [자율주행 ▼]                        │
│ 모니터 2: ( 자율주행 · 수동주행 · 인터랙션 )   │ [CPU 부하] [강제 종료]                       │
│ 상태: 적용됨 (rev 7)                         │ 비교: 대상 / 비대상 VM 상태·지연·복구 시간     │
├ 수동주행 입력 ─────────────────────────────┴─────────────────────────────────────────┤
│ 모드: MANUAL 일 때만 입력 받음   [▲][◀][▼][▶]  (키보드 화살표·WASD)   [자율주행 재개]   │
└────────────────────────────────────────────────────────────────────────────────────┘
```

| 영역 | 동작 | 데이터 |
| --- | --- | --- |
| 화면 배치 | 모니터 1·2 에 띄울 화면 선택·교체, 적용 상태 표시 | `PUT /api/v1/displays/{display-0\|display-1}/route` (REST-24, 미구현 -129) |
| 격리 시연 | 대상 VM 에 부하·종료 주입, 대상과 비대상의 상태·명령 주기·복구 시간 비교 | 격리 시연 API (-135, 에이전트 `agent.command`), 메트릭 |
| 수동주행 입력 | 키 입력 → 수동주행 VM. **MANUAL 이 아니면 백엔드가 버린다** | `WS /ws/v1/drive` → MQTT-11 (MQTT 계약 §7, 미구현) |
| 자율주행 재개 | (계약 v1.5) AUTO_READY 가 되면 **자동으로** 3·2·1 뒤 AUTO. 카운트다운 중 [취소 — 수동주행 유지]. 취소했으면 [자율주행 재개]로만 | 자동: `drive.resume.accepted`(`requested_by: auto`), 취소: `DELETE /api/v1/drive/resume` → MQTT-13 `drive.resume.cancel_requested`, 재개: `drive.resume.requested` (MQTT 계약 §5.2·§6) |

- 수동주행 입력과 재개 버튼은 인터랙션 VM 화면에도 있지만, 모니터는 터치가 없으므로 **실제 조작은 여기서** 한다.

## 5. 모니터 화면

모니터 화면은 **조작 없이 멀리서 읽히게** 만든다: 큰 글자, 상태는 색과 글자 둘 다, 깜빡임은 장애에만.

### M-01 모니터 1 — 3분할

```text
┌ 자율주행 · AUTO · gen 4        속도 0.50 m/s  조향 +0.07  장애물 없음              ┐
├─────────────────────┬─────────────────────┬─────────────────────┤
│ 자율주행    [정상]   │ 수동주행    [정상]   │ 인터랙션    [정상]   │
│ Zephyr · autonomous │ Zephyr · manual     │ Debian · message-board │
│ ▶ 차량 제어 중       │ 예비 — 준비됨        │ ─ 최근 알림 5건 ─      │
│ 명령 50 Hz           │ 명령 50 Hz (v=0)     │ 수동주행으로 즉시 인계  │
│ 인지 차선 0.05 m     │ 키 입력 없음          │ 자율주행 명령 끊김      │
└─────────────────────┴─────────────────────┴─────────────────────┘
```

| 칸 | 보여 줄 것 |
| --- | --- |
| 위쪽 띠 | 주행 모드·세대, 활성 앱, 안전 플래그, 차량 속도·조향·장애물. 배터리 전압은 ESP32 측정 회로가 없어 표시하지 않는다 (계약 v1.1 `batt_v` 선택) |
| 각 칸 공통 | VM 이름(역할), OS·app_id, 상태 배지(복구 중이면 경과 시간), 차량 제어 중 표시 |
| 자율주행 | 명령 주기, 마지막 명령, 인지 요약 |
| 수동주행 | 예비 준비 / 운영자 운전 중, 키 입력 |
| 인터랙션 | 최근 알림 (모드 전환·장애·복구) |

장애가 나면 **그 칸만** 빨강 → 노랑(복구 중) → 초록으로 바뀌어 격리가 눈에 보이게 한다.

**시뮬레이터 구성**: 세 번째 칸이 자동으로 **시뮬레이터**가 된다 (시뮬레이터 위치가 1초 안에 오면, 화면 배치 계약 v1.1 §5.6). 칸의 틀(머리·역할·본문)은 다른 두 칸과 같고, 본문은 트랙 탑뷰 + 속도·조향·장애물, 맨 아래 **네비게이션 알림 띠**(그 VM 이 죽으면 "응답 없음 — 주행은 그대로", D8 격리). 칸을 누르면 `/sim`. 자율주행·수동주행 칸 위쪽에는 같은 차의 **1인칭 시점**(시뮬레이터 위치로 그린 원근 그림)이 나온다 — 지금 운전하는 쪽만 또렷하고, 자율 칸은 인지 값(차선 오프셋·장애물), 수동 칸은 조작 키(◀ ▲ ▼ ▶ 정지)를 겹친다. 눌린 키는 웹 입력이 없으면 수동 명령을 거꾸로 읽어 켠다 (주행 상태에 키가 없다).

MQTT 계약 v1.4 실제 서킷(`world.track.centerline`)이면 (2026-10-22, 시나리오 §4·§4-2):

- 탑뷰: 실제 서킷 — 아스팔트·연석·잔디·흙(코너 바깥)·벽·관중석·사진 나무·출발선. 차는 판정과 같은 실제 크기(좁은 칸에서는 최소 크기), 장애물은 종류(콘·박스·타이어)대로.
- 1인칭: 하늘·구름·먼 산, 사진 나무, 관중석, **출발 신호 다리**(빨간 불 다섯 개, F1 방식), 장애물. 자율 칸은 **인식 박스**(종류·실제 거리). 위에 랩 시간, 출발 신호 중에는 신호판과 "모두 꺼지면 출발", 꺼지면 "출발!" (부정 출발이면 "부정 출발!").
- 표시 단위: 속도 km/h, 거리 m — 모의 값 × 트랙 `real_m` 비율 (모드 띠·목표 속도·상세 화면도 같다). 계약 값은 m·m/s 그대로.
- 위치는 10 Hz 로 오므로 화면은 속도·조향으로 0.3초까지 이어 그린다 (`world.time_scale` 반영). 캔버스는 칸마다 30 fps 상한, 보드가 느리면 품질 `low`(나무·관중·구름 빼기)로 낮춘다 — 실보드에서 재고 정한다.
