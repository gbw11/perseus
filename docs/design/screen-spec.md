# 화면 정의서

웹(관리 콘솔)과 모니터 2대에 **어떤 화면이 들어가고, 각 화면이 무엇을 보여 주고 무엇을 조작하는지**를 정한다.
디자인(스티치)은 이 문서의 화면 목록·정보·동작을 기준으로 만들고, 구현은 디자인을 따른다.

> 상태: 초안 (2026-10-20, S15P31E110-50). Low-Fi 정의이며 모양·색은 디자인에서 정한다.
> 근거: 노션 요구사항 명세 "관리 UI·화면"(UI-01~09, DS-01~02), [RC카 시나리오](../scenario-rc-car.md) §4·§5,
> [MQTT 계약](../contracts/mqtt-contract-v1.md), [VM 관리 API 계약](../contracts/vm-api-contract-v1.md), 노션 API 명세(REST·WS).
> 어긋나면 **구현된 코드 → 저장소 문서(계약) → 노션** 순으로 따른다 (2026-10-21, S15P31E110-249). 화면이 아직 구현되지 않은 API·값을 쓰는 곳은 "미구현"으로 적는다.

## 1. 기기와 역할

| 기기 | 누가 보나 | 역할 | 입력 |
| --- | --- | --- | --- |
| **웹 — 관리 콘솔** (노트북 브라우저) | 운영자 | 시연을 **조작**하고 VM 을 **관리**한다 | 마우스·키보드 |
| **모니터 1** (RPi4 HDMI, 27인치) | 관람자 | VM 3개 **전체 상황** (3분할) | 없음 |
| **모니터 2** (RPi4 HDMI) | 관람자 | 운영자가 고른 VM 1개 **상세** | 없음 |

- 모니터는 보여 주기만 한다. 터치가 없으므로 **모든 조작은 웹에서** 한다 (수동주행 키 입력 포함).
- 모니터 화면은 웹 페이지로 만들고 dom0 표시 서비스가 키오스크 브라우저로 띄운다. 어느 모니터에 무엇을 띄울지는 웹의 화면 라우터(DS-01)가 정한다.
- 27인치가 모니터 1·2 중 어느 쪽인지는 설치 때 정한다 (§7 Q1). 큰 쪽을 3분할(모니터 1)로 쓰는 것을 제안한다.

```text
            ┌──────────── 웹 (운영자) ────────────┐
            │ 대시보드 · VM · 자원 · 시연 제어 · 이벤트 │
            └──────┬───────────────┬──────────────┘
          REST·WS  │               │ 화면 배치 (REST-24)
                   ▼               ▼
        Spring 백엔드 ──WS-04──▶ dom0 표시 서비스 ──HDMI──▶ 모니터 1 (3분할) / 모니터 2 (상세)
                   │                                       ▲
                   └── MQTT (주행 상태·이벤트) ─────────────┘
```

## 3. 공통 표시 규칙

| 규칙 | 내용 | 근거 |
| --- | --- | --- |
| 상태 배지 4종 | 정상(초록) · 장애(빨강) · 복구 중(노랑, 경과 시간) · 정지(회색). 화면마다 다른 말을 쓰지 않는다 | RC카 시나리오 §4.3 |
| 주행 모드 4종 | 자율주행 `AUTO` · 수동주행 `MANUAL` · 재개 가능 `AUTO_READY` · 안전 정지 `SAFE_STOP` | MQTT 계약 §5.2 |
| 앱 역할색 | 자율주행 · 수동주행 · 인터랙션을 색으로 구분 (모든 화면 같은 색) | |
| VM 식별 | Linux 는 배포판(Debian·Ubuntu), Zephyr 는 **같은 OS 이므로 이름·역할로 구분** ("자율주행 VM", "수동주행 VM") | DS-02 |
| 준비 ≠ 제어권 | 예비 VM 이 "준비됨" 인 것과 "차량 제어 중" 인 것을 다른 표시로 쓴다 | UI-09 |
| 의도적 정지 | 콘솔에서 끈 VM 은 장애가 아니라 '정지' 로 표시, 자동 재시작하지 않음 | RC-04, 시나리오 §4.3 |
| 시각 | 경과 시간("3초 전")은 화면 시계 기준. 보드 간 시각을 비교해 판정하지 않는다 | MQTT 계약 §1 |

### W-02 대시보드 — 주행 통합 상태 (UI-09)

데모 중 운영자가 계속 띄워 두는 화면. **한 화면에서 "지금 누가 차를 몰고 있고, 넘길 준비가 됐는지"** 가 보여야 한다.

```text
┌ 주행 모드: 자율주행 (AUTO · gen 4)   활성: 자율주행 VM   안전: 구동 허용 ─────────────┐
├──────────────────────┬──────────────────────┬──────────────────────────────────┤
│ 자율주행 VM  [정상]   │ 수동주행 VM  [정상]   │ 인터랙션 VM  [정상]              │
│ ▶ 차량 제어 중        │ 예비 — 준비됨         │ 알림 표시 중                     │
│ 명령 50 Hz           │ 명령 50 Hz (v=0)     │ 에이전트 연결됨                  │
├──────────────────────┴──────────────────────┴──────────────────────────────────┤
│ 차량: 0.50 m/s · 조향 +0.07 rad · 장애물 없음 · 비상정지 버튼 안 눌림             │
│ 인지(젯슨): 유효 · 15 Hz · 마지막 수신 0.1초 전                                     │
├────────────────────────────────────────────────────────────────────────────────┤
│ 최근 이벤트 5건  (→ 이벤트 타임라인)                                                │
└────────────────────────────────────────────────────────────────────────────────┘
```

| 독립 항목 (UI-09) | 값 | 데이터 |
| --- | --- | --- |
| 주행 모드 | AUTO·MANUAL·AUTO_READY·SAFE_STOP + 세대 | `vehicle.control` (MQTT-09) |
| 활성 VM | 차량 명령을 실제로 전달받는 앱 | `vehicle.control.active_app` |
| 예비 VM 준비 | 수동주행 명령 신선 여부 (100 ms) | `drive.command` 수신 (MQTT-06) |
| 안전·구동 허용 | E-stop, 와치독, 장애물 플래그 | `vehicle.status.flags` (MQTT-10) |
| 인지 유효성 | 젯슨 결과 수신 주기·마지막 수신 | `perception.result` (MQTT-06) |
| VM 상태 | 도메인 상태, 에이전트(Linux) | `GET /api/v1/vms` |

### W-07 시연 제어 (UI-08, DS-01, 수동주행 입력)

데모 진행자가 쓰는 화면. 세 영역을 한 화면에 둔다.

```text
┌ 화면 배치 (DS-01) ─────────────────────────┬ 격리 시연 (UI-08) ─────────────────────────┐
│ 모니터 1: [3분할 ▼]                          │ 대상 VM: [자율주행 ▼]                        │
│ 모니터 2: ( 자율주행 · 수동주행 · 인터랙션 )   │ [CPU 부하] [강제 종료]                       │
│ 상태: 적용됨 (rev 7)                         │ 비교: 대상 / 비대상 VM 상태·지연·복구 시간     │
├ 수동주행 입력 ─────────────────────────────┴─────────────────────────────────────────┤
│ 모드: MANUAL 일 때만 입력 받음   [▲][◀][▼][▶]  (키보드 화살표·WASD)   [자율주행 재개]   │
└────────────────────────────────────────────────────────────────────────────────────┘
```

| 영역 | 동작 | 데이터 |
| --- | --- | --- |
| 화면 배치 | 모니터 1·2 에 띄울 화면 선택·교체, 적용 상태 표시 | `PUT /api/v1/displays/{display-0\|display-1}/route` (REST-24, 미구현 -129) |
| 격리 시연 | 대상 VM 에 부하·종료 주입, 대상과 비대상의 상태·명령 주기·복구 시간 비교 | 격리 시연 API (-135, 에이전트 `agent.command`), 메트릭 |
| 수동주행 입력 | 키 입력 → 수동주행 VM. **MANUAL 이 아니면 백엔드가 버린다** | `WS /ws/v1/drive` → MQTT-11 (MQTT 계약 §7, 구현 -154) |
| 자율주행 재개 | AUTO_READY 에서만 활성 | `drive.resume.requested` (MQTT 계약 §6). **콘솔(백엔드)에서 보내는 경로는 미구현** — 계약상 재개 요청은 메시지 보드 VM 만 낸다 (§6·§9). 콘솔 경로가 생기기 전까지 버튼은 비활성·안내만 |

- 모니터는 터치가 없으므로 **수동주행 입력은 여기서** 한다. 재개는 지금 메시지 보드 VM 이 내는 `drive.resume.requested` 로만 된다. 재개 성공은 `drive.mode.changed`(`to: AUTO`, `reason: resume_requested`)로 확인한다 — 수락·거절 응답 이벤트는 없다.
- 화면 배치 API 의 `view` 값은 지금 `os-face` 하나다. 모니터 1 의 3분할을 위해 `split` 같은 값이 더 필요하다 (§7 Q3).

### W-08 이벤트 타임라인 (UI-07)

| 항목 | 내용 |
| --- | --- |
| 보여 줄 것 | 시간순 이벤트. 종류별 구분: 모드 전환(`drive.mode.changed`, 사유 5.2 전환 표) / 주행 앱 장애(`drive.fault.detected`) / VM 생성·삭제·상태 변화(`vm.*`) / 에이전트 상태 / 복구(`recovery.*`, 복구 서비스 구현 후) / 시연 명령(`demo.command.*`). 자율주행 **자동 복귀는 없다** — 복구 뒤 `AUTO_READY`(재개 가능)까지만 가고 재개는 사람이 한다 (시나리오 §4.2) |
| 동작 | 종류·VM·심각도 필터, 실시간 추가 |
| 데이터 | `GET /api/v1/events`, `WS /ws/v1/events`. 차량 이벤트(`drive.mode.changed`, `drive.fault.detected`)는 백엔드가 MQTT 에서 받아 저장 (-154). 종류 필터 값은 백엔드 `EventType` 12종뿐이며, 모르는 값을 보내면 REST 는 422, WS 구독은 `EVENT_TYPE_UNSUPPORTED` 로 구독 전체가 거부된다 |

## 5. 모니터 화면

모니터 화면은 **조작 없이 멀리서 읽히게** 만든다: 큰 글자, 상태는 색과 글자 둘 다, 깜빡임은 장애에만.

### M-01 모니터 1 — 3분할

```text
┌ 자율주행 · AUTO · gen 4        속도 0.50 m/s  조향 +0.07  장애물 없음               ┐
├─────────────────────┬─────────────────────┬─────────────────────┤
│ 자율주행    [정상]   │ 수동주행    [정상]   │ 인터랙션    [정상]   │
```

### M-02~04 모니터 2 — 상세

| 화면 | 주 영역 | 옆 영역 |
| --- | --- | --- |
| M-02 자율주행 | 인지 결과 그림 (차선·장애물·차 위치, 15 Hz). 백엔드 중계(`/ws/v1/drive/state`)는 인지 결과를 차선 오프셋·방향 오차·**장애물 개수**·`stop` 으로만 준다 → 장애물 위치는 그릴 수 없다 | 목표 속도·조향 게이지, 명령 주기, 차선 오프셋·방향 오차 |
| M-03 수동주행 | 대기 / 운영자 운전 중, 수동 앱의 마지막 명령(목표 속도·조향). 눌린 키는 백엔드 중계에 없어 표시하지 않는다 | 목표 속도·조향, 활성 여부 |
| M-04 인터랙션 | 알림 타임라인 (`drive.mode.changed` · `drive.fault.detected`). `message.posted` 는 백엔드가 저장·중계하지 않아(개수만 셈) 지금은 표시하지 않는다 | 자율주행 재개 상태 (AUTO_READY 여부) |

데이터는 MQTT 주행·앱 토픽 (MQTT 계약 §5·§6)을 **백엔드가 중계**한 것이다: `WS /ws/v1/drive/state`(주행 통합 상태)와 `WS /ws/v1/events`(이벤트) — §7 Q5 결정. 화면에 쓸 수 있는 값은 백엔드 `DriveState`(모드·세대·활성 앱·사유, 차량 속도·조향·플래그, 앱별 명령 신선도·주기·마지막 명령·heartbeat, 인지 요약)에 있는 것뿐이다.
가짜 시나리오로 먼저 돌려 볼 수 있다 (`frontend/apps/vm-screens`).
