# YOLOP 320×320 자산과 입출력 계약

선택 자산은 `yolop-320x320-rvc2-ov2021.4-sh6-v1`이다. 기계 판독 값은 [manifest](manifests/yolop-320x320-rvc2-ov2021.4-sh6.json)를 따른다. 이 명세는 자산·픽셀/tensor 계약이며 RC 트랙 정확도나 깊이와의 동시 실행 수락을 뜻하지 않는다. 구현 과정과 장치별 검사 결과는 `Jetson-drive-docs/making-reports/0012-yolop-assets.md`에 둔다.

## 파일과 출처

| 항목 | 고정 값 |
|---|---|
| 모델 | Luxonis `yolop_320x320` |
| blob | `yolop_320x320_openvino_2021.4_6shave.blob`, 15,973,184B |
| blob SHA256 | `8bc407f90814c6092ce0d76f7ce8cee0aaec68236358113946fe0134a655c437` |
| 대상 | OAK-D-Lite / RVC2(Myriad X), DepthAI 2.29.0.0 |
| 컴파일 요청·header | OpenVINO 2021.4, SHAVE6 / CMX slice6, `-ip U8 -op FP16` |
| 자산 정책 | 로컬 파일 사용. 부팅 시 다운로드·모델 변환 없음 |

[Luxonis model-zoo 고정 revision](https://github.com/luxonis/depthai-model-zoo/tree/ac2eff9570af531ebd042765655e8940c2573da4/models/yolop_320x320)의 IR XML/BIN을 사용한다. 두 파일의 크기·SHA256은 해당 `model.yml`과 대조한다. BIN의 CDN 주소는 가변이므로 URL만으로 자산을 승인하지 않는다. [공개 변환 서비스](https://github.com/luxonis/blobconverter/tree/29887eb6dbe74f9afb32ecd3de646388ea9e839e)는 이 고정 IR에서 Myriad blob을 생성하는 데 사용하며 운영 의존성으로 추가하지 않는다.

모델의 MIT 선언은 model-zoo metadata의 원 저자 링크에 근거한다. 자산 배포 시 [YOLOP 저작권·허가문](licenses/YOLOP-LICENSE.txt)과 [Model Zoo 저작권·허가문](licenses/Luxonis-Model-Zoo-LICENSE.txt)을 함께 보존한다. 특정 원 `.pth`/ONNX checkpoint에서 이 IR을 재생성한 export revision과 원격 compiler의 세부 build는 확인되지 않아 manifest에 `null`로 남긴다. 원 저자 repository revision을 가중치 export revision으로 해석하지 않는다.

대용량 blob/IR은 Git에 넣지 않는다. 로컬 작업 사본은 `build/model-assets/yolop-320x320-rvc2-ov2021.4-sh6`, 배포 사본은 실행 환경의 외부 자산 경로에 둔다. 보존 묶음·검증 근거 위치는 `making-reports`에서 관리한다.

## 입력

`images`는 **uint8 BGR planar**, 논리 shape `[1,3,320,320]`, 총307200B다. DepthAI frame type은 `BGR888p`다. SDK의 `U8F`는 이 blob의 unsigned8 타입이며 정규화된 float 입력을 뜻하지 않는다.

IR에는 BGR→RGB 채널 역전과 affine 정규화가 이미 포함돼 있다. host에서 RGB 변환·255 나눗셈·ImageNet 정규화를 중복 적용하지 않는다. 내장 RGB 순서의 FP16 scale은 `[0.017120361328125,0.0175018310546875,0.017425537109375]`, bias는 `[-2.1171875,-2.03515625,-1.8046875]`다. 이 값은 실제 IR weights에서 읽은 값이며 이상적인 소수식을 다시 계산해 대체하지 않는다.

프로젝트의 연결 프로필은 **640×360→320×180 resize, 위/아래70px black padding**인 letterbox를 사용한다. 이는 원 모델의 필수 shape와 별개인 프로젝트 선택이다. 연속 image-edge 좌표에서 `u_nn=0.5*u_source`, `v_nn=0.5*v_source+70`이며 유효 내용 ROI는 `[0,70,320,250)`이다. padding은 관측이 아니다. bbox/마스크를 원 영상에 연결할 때 이 변환을 역으로 적용한다. 실제 ImageManip의 보간·반올림·색상 pixel equivalence는 그래프 연결 단계에서 golden 입력으로 검증해야 한다.

[고정 Luxonis 예제](https://github.com/luxonis/oak-examples/tree/5d6f8b8fa55f80c5958dbd7f72733cbffc37a4d4/gen2-yolo/yolop)는320×320 stretch를 사용하며 letterbox를 제안만 한다. 예제의 OpenCV BGR bytes와 `RGB888p` tag 혼용, 인위적인 host timestamp, Torch 후처리를 그대로 복사하지 않는다.

## 출력과 해석

| 이름 | 논리 shape | 자료형 / 유효 bytes | 의미 |
|---|---|---|---|
| `det_out` | `[1,6300,6]` | little-endian FP16 /75600 | 각 행 `[cx,cy,w,h,objectness,vehicle_score]` |
| `drive_area_seg` | `[1,2,320,320]` | little-endian FP16 /409600 | 배경/주행 영역 후보의 sigmoid score |
| `lane_line_seg` | `[1,2,320,320]` | little-endian FP16 /409600 | 배경/차선 후보의 sigmoid score |

검출 좌표는320×320 NN 입력 pixel 기준이다. box는 이미 grid/anchor decode된 proposal이며 host에서 `objectness*vehicle_score`, xywh→xyxy, NMS를 수행한다. 단일 vehicle class이므로 박스·콘·일반 장애물 검출기로 간주하지 않는다. segmentation은 channel 축 argmax로0배경/1전경 후보를 얻는다. score를 측정 불확실성이나 보정된 확률로 해석하지 않는다. mask는 거리·통행 허가·FREE·주차칸의 최종 판정이 아니다.

원 예제 confidence0.5/NMS IoU0.3은 비교용 초깃값이다. RC 트랙 수락값은 실제 영상에서 별도로 정한다. 지역 parser는 아직 구현하지 않았으므로 manifest의 `local_parser_revision`은 `null`이다. 후속 parser는 원 입력 source key·시각과 모델/전처리 revision을 유지해야 한다.

## 메모리 배치의 두 층

DepthAI2.29 `Blob.networkInputs/Outputs`의 `dims`는 fastest dimension부터 나열된다. 논리 shape를 SDK dims 그대로 reshape하지 않는다. SDK BlobReader는 stride 필드를 건너뛰므로 `strides=[]`는 contiguous의 증거가 아니다.

컴파일된 **이 자산의 I/O buffer descriptor**는 다음과 같다. 원 blob과 고정 OpenVINO serializer로 확인한 byte stride이며 XLink packet offset이 아니다.

| 이름 | SDK dims / fastest→slowest | 원 byte stride / fastest→slowest | 해당 compiler buffer 내 offset |
|---|---|---|---:|
| images | `[320,320,3,1]` / WHCN | `[1,320,102400,307200]` | 입력0 |
| det_out | `[6,6300,1]` / WHC | `[2,12,75600]` | 출력0 |
| drive_area_seg | `[320,320,2,1]` / WHCN | `[2,640,204800,409600]` | 출력75648 |
| lane_line_seg | `[320,320,2,1]` / WHCN | `[2,640,204800,409600]` | 출력485248 |

논리 출력 합은894800B지만 compiler 출력 buffer는894848B다. detection 뒤48B padding이 있다. 임의의 하나의 연속 배열로 세 출력을 이어 붙이지 않는다. 실제 `NNData.getRaw().tensors`의 offset/stride/전체 buffer 길이는 **기동 후 별도로 검사**한다. compiler descriptor를 live NNData packet layout으로 단정하지 않는다. 원 SDK `getLayerFp16(name)` 결과를 초기 golden 대조에 사용할 수 있지만 Python list 복사 비용을 운영 성능에서 제외하지 않는다.

## 수동 자산 검사

Python3.11 이상에서 아래 검사는 stdlib만 사용한다. `--with-depthai`를 명시할 때만 설치된2.29 SDK를 import해 Blob metadata와 host graph version을 대조한다. Device를 만들지 않고 camera lock·broker·DB를 열지 않는다. 운영 기동의 선행 gate로 자동 연결하지 않는다.

```bash
python vehicle/Jetson/scripts/verify_yolop_asset.py \
  --asset-dir /path/to/yolop-320x320-rvc2-ov2021.4-sh6-v1

python vehicle/Jetson/scripts/verify_yolop_asset.py \
  --asset-dir /path/to/yolop-320x320-rvc2-ov2021.4-sh6-v1 \
  --with-depthai
```

현재 자산의 SHA·header·tensor 계약 확인과 실제 OAK 적재/추론은 서로 다른 증거다. SHAVE6·1inference thread는 첫 연결의 자원 설정 후보이며 StereoDepth와 동시15Hz를 보장하지 않는다. NN_READY는 현재 pipeline의 fresh NN 출력과 원 입력 metadata/parser 검증 후에만 판정한다.
